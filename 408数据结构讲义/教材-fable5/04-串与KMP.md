# 408·第四章 串(重点:KMP)

> 这章很薄:串的存储两句话说完,朴素匹配你闭眼能写,**全章的分值和难度都压在 KMP 上——具体说,压在"手算 next 数组"上**。408 几乎不让你写 KMP 代码,但隔三差五让你算 next 值,而 next 恰好是全考纲约定最混乱的知识点。本章的任务:让你拿到任何一种约定都能现场推,而不是背一套公式去赌。

## 4.0 串是什么

串 = 元素类型限定为字符的线性表。你在 C 教材 07 章跟 `char s[]` 和 `'\0'` 搏斗过,概念上没有任何新东西。408 需要知道的存储姿势:

- **定长顺序存储**:`char ch[MAXLEN]` + 一个 `length` 变量(不靠 `'\0'`,靠显式长度——和 C 字符串的习惯不同,读题注意)。
- **堆分配存储**:`char *ch` + `length`,malloc 出来,能扩。
- 块链存储:认识即可,基本不考。

⚠ 408 的串**下标通常从 1 开始**(`s[1]` 是第一个字符),和 C 的从 0 起不同。做题先看约定,本章下面全用 1 起。

## 4.1 朴素匹配(Brute Force):先懂它的笨,才懂 KMP 的巧

在主串 S(长 n)里找模式串 P(长 m):从 S 的每个位置试着对齐 P,逐字符比,失配就把 P **整体右移一格、从头再比**。

```
S: a b a b a b c
P: a b a b c          ← 比到第5个字符失配
       a b a b c      ← P 右移一格,i 也回退,从头比
```

最坏 O(n×m):比如 S = "aaaaaaab"、P = "aaab",每次都比到最后一个才失配。

**它笨在哪?看上图失配那一刻**:我们已经知道 S 的前 4 个字符是 "abab"(因为刚和 P 比对成功过)。回退重比,等于把这个情报扔了。KMP 的全部思想就一句:

> **失配时,利用"已匹配部分"的情报,让模式串一步滑到位,主串指针 i 永不回退。**

## 4.2 KMP 的核心:失配后 P 该滑到哪

失配瞬间,已匹配的部分是 P 的一个前缀(上例:"abab")。P 右滑之后还想活着,必须满足:**滑动后 P 的开头若干字符,与已匹配部分的结尾若干字符重合**。

盯着 "abab" 看:它的开头 "ab" 和结尾 "ab" 一样——术语叫 **"abab" 有一个长度为 2 的相等前后缀(border)**。所以 P 可以直接滑到"让自己的前 2 个字符对住已匹配部分的后 2 个字符"的位置,中间跳过的对齐方式**不可能成功**(可以自己用反证法体会:若中间某个对齐能成,就意味着 "abab" 有更长的 border)。

于是每个失配位置需要的情报只有一个数:**"失配字符之前的那段"的最长相等前后缀有多长**。把每个位置的这个数预先算好存进数组——这就是 **next 数组**。它只和 P 自己有关,和主串无关,所以能预处理。

### 手算最长相等前后缀(一切约定的公共内核)

规则:真前缀(不含最后一个字符)和真后缀(不含第一个字符)中,最长的相等对。**整串自己不算!**

| 串 | 真前缀们 | 真后缀们 | 最长 border 长度 |
|---|---|---|---|
| a | (无) | (无) | 0 |
| ab | a | b | 0 |
| aba | a, ab | a, ba | 1("a") |
| abaa | a,ab,aba | a,aa,baa | 1("a") |
| abaab | a,ab,aba,abaa | b,ab,aab,baab | 2("ab") |
| aaaa | a,aa,aaa | a,aa,aaa | 3("aaa") |

这个手艺练熟,任何约定的 next 都是它的换皮。

## 4.3 next 数组:一个内核,两套皮

**王道/严蔚敏约定(408 主流,1 起下标)**:`next[j]` = 失配发生在 `P[j]` 时,j 应该退到的位置。规定 `next[1] = 0`(第一个字符就失配,主串 i 前进一格)。其余:

> **next[j] = P[1 .. j-1] 的最长 border 长度 + 1**

**手算全流程,以 P = "abaabc" 为例**(把 4.2 的表直接搬来用):

| j | P[j] | 它前面的串 P[1..j-1] | 最长 border | next[j] = border+1 |
|---|---|---|---|---|
| 1 | a | (空) | — | **0**(规定) |
| 2 | b | a | 0 | 1 |
| 3 | a | ab | 0 | 1 |
| 4 | a | aba | 1 | 2 |
| 5 | b | abaa | 1 | 2 |
| 6 | c | abaab | 2 | 3 |

**next = 0 1 1 2 2 3**。考场三步:①写下每个 j 前面的串;②求各自最长 border(4.2 手艺);③加 1,首位填 0。一分钟一条龙。

**另一套皮(0 起下标,教科书/工程界)**:`next[j]` 直接等于 `P[0..j-1]` 的最长 border 长度,首位填 -1 或 0,不加一。**换算关系:王道版 = 0 起版整体 +1。** 拿到题先看两处:下标从几起?next 首位给的是 0 还是 -1?对上号再动笔。

### nextval:再抠一步的优化(408 也考手算)

场景:P[j]='a' 失配,next 让你退到 next[j] 一看——那儿**还是 'a'**,必然再失配一次,白跳一步。优化:若 `P[j] == P[next[j]]`,就把 `nextval[j]` 直接抄成 `nextval[next[j]]`(一步到位跳过必败点);否则 `nextval[j] = next[j]`。

例:P = "aaaab",next = 0 1 2 3 4。逐位算 nextval:
- j=1:规定 0。
- j=2:P[2]='a',P[next[2]]=P[1]='a',相同 → 抄 nextval[1]=0。
- j=3、4 同理逐级抄 → 全是 0。
- j=5:P[5]='b',P[next[5]]=P[4]='a',不同 → nextval[5]=next[5]=4。

**nextval = 0 0 0 0 4**。直觉核对:前四个 'a' 中任何一个失配,退到别的 'a' 毫无意义,直接 0(主串前进)——合理。

## 4.4 KMP 匹配过程与复杂度

有了 next,匹配代码几乎和朴素版一样,只是失配时 `j = next[j]` 而 **i 不动**:

```c
int kmp(char S[], int n, char P[], int m, int next[]) {  // 下标 1 起
    int i = 1, j = 1;
    while (i <= n && j <= m) {
        if (j == 0 || S[i] == P[j]) { i++; j++; }   // 匹配(或 j 退无可退),双双前进
        else j = next[j];                            // 失配:P 滑动,i 不回退
    }
    return (j > m) ? (i - m) : 0;    // 匹配成功返回起始位置
}
```

复杂度 **O(n + m)**:i 从不回退最多走 n 步;j 每次失配只减不增、每次匹配才加 1,总账算下来也是线性。对比朴素 O(n×m)。

408 还爱考一问:"KMP 相比朴素匹配的本质改进是?"——标准答案:**主串指针不回溯,利用模式串自身的部分匹配信息(next)决定滑动距离**。

## 4.5 next 是怎么被 O(m) 算出来的:让模式串对自己跑一遍 KMP

> 本节回答 Henry 暑假的一个好问题:"手算我会了,可**代码**怎么求 next?我能想到的笨办法——对每个 j 从头数一遍 border——那不就 O(m²) 了?为了求 next 反而更亏?" 前半句对,后半句不对。先算清这笔账,再给出真正的 O(m) 解法——它的思想是全章最漂亮的一处。

### 先算总账:笨版真"亏"吗

设主串长 n、模式串长 m:

| 方案 | 建 next | 匹配 | 总成本 |
|---|---|---|---|
| 朴素匹配(压根不建 next) | — | — | **O(n·m)** |
| KMP + 笨版 next(每个 j 从头重数 border) | O(m²) | O(n) | **O(n + m²)** |
| KMP + O(m) next(本节) | O(m) | O(n) | **O(n + m)** |

要害:**n 是大文本,m 是小模式串,不在一个数量级**。next 只在小小的 m 上建**一次**,却拿去大大的 n 上反复用。代数字:`n=100 万、m=100` 时,朴素约 `10⁸`;笨版 KMP 约 `10⁶ + 10⁴`——那个 `m²=10⁴` 只占约百分之一,忽略不计。所以笨版**不亏**:短串上花一次性小钱,省下长文本上的巨款。但预处理也能做到 O(m),一分不浪费——而这个做法,会让你彻底看穿 KMP 的灵魂。

### 洞察:border 会"接力生长",不必每次从零重数

笨版的浪费在于:求 `P[1..i-1]` 的 border 时,把刚才求 `P[1..i-2]` 时的成果全扔了、从零再数。可这两者高度相关。抓住一句话:

> **长一位的前缀,它的最长 border,是从短一位的 border 上"长"出来的。**

已知 `P[1..i-1]` 的最长 border 长度是 k(即"开头 k 个字符 = 结尾 k 个字符")。现在末尾多来一个字符 `P[i]`,问 `P[1..i]` 的最长 border 多长?只有两条路:

- **能接上**:这条 border 后面本该跟的字符是 `P[k+1]`。若它恰好等于新字符 `P[i]`,旧 border 直接加长一位 → 新 border = k+1。✅
- **接不上**(`P[k+1] ≠ P[i]`):这条 border 断了,但**别从零重来**。退而求其次,去找 `P[1..i-1]` 更短的 border 再试——而那个"次长 border",正是**这条 border 自己的 border**(border 套 border),它**早就在 next 数组里算好了**。取出来,拿 `P[i]` 再试接;反复,直到接上、或退到 0。

看见那个自我指涉没有:**求 next 的过程,回过头又用到已经求好的 next**(border 的 border)。next 帮着算 next——这就是它做到 O(m) 的秘密。

### 说穿了,这就是"KMP 匹配自己"

把上面两条翻译一下,和 4.4 的匹配代码并排看:

| 求 next 时的动作 | 4.4 匹配时的动作 |
|---|---|
| 新字符能接上 → 前进一位 | 字符匹配 → `i++, j++` |
| 接不上 → 退到更短的已知 border | 失配 → `j = next[j]` |

**分毫不差。** 所以求 next 的本质是:**让 P 既当"主串"、又当"模式串",对自己跑一遍 4.4 的 KMP**。指针 i 在前探路(指向新字符,永不回头),指针 j 在后跟着比(记录当前前缀对齐到哪儿,失配才按 next 缩回)。i 一路不回退 → O(m);j 只在失配时减、匹配时加,涨跌摊平也 O(m);合计 **O(m)**,一分不浪费。

```
 P 当“文本”:  a b a a b c      ← i 从左扫过来,永不回头
 P 当“模式”:  a b a a b c      ← j 跟着比,一失配就 j=next[j] 缩回
              把自己按在自己身上滑,当场滑出来的“已对齐长度”就是 border
```

### 手推 next("abaabc"):前 4 步我走,⑤起你补

固定 `next[1]=0`;两指针初始 `i=1, j=0`。每一步只看 `P[i]` 与 `P[j]`:
- **`j==0` 或 `P[i]==P[j]`**:`i++`、`j++`,并写下 `next[i]=j`;
- **否则失配**:`j = next[j]`,i 不动,原地再比。

| 步 | 当前 (i, j) | 比 `P[i]` vs `P[j]` | 判定 | 动作 | 记录 |

| ② | (2, 1) | b vs a | ✗ | j→next[1]=0(i 不动) | — |

| ④ | (3, 1) | a vs a | ✓ | i→4, j→2 | **next[4]=2** |

## 易错点

1. 求 border 时把**整串自己**算进去(它不是真前缀/真后缀)。
2. 两套约定混用:王道版要 +1、首位 0;0 起版不加 1、首位 -1。先认约定再下笔。
3. nextval 抄的是 **nextval**[next[j]],不是 next[next[j]]——要用已优化的值,才能层层击穿。
4. 手算 next 全对但匹配位置算错:成功时返回的是 `i - m`(起始位置),不是 i。
5. "next 只和模式串有关,与主串无关"——判断题原话,对。
