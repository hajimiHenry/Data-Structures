# 12 递归

> 这一章的目标只有一个:让你在进 408 二叉树之前,把"函数调用自己"这件事从**魔法**变成**机械**。树的三种遍历、二叉树求高度、判等、销毁——全是这一章的直接复用。

## 12.0 你其实已经见过调用栈了

回想你调试 use-after-free 时 ASan 吐出来的这段:

```
#0 print_list list.c:120
#1 main :63
```

`#0 #1` 那一列你已经会读:"main 调了 print_list,此刻停在 print_list 里"。这个"谁调了谁"的叠罗汉,就是**调用栈**——每调用一个函数,系统就往栈上压一层(存着这次调用的参数、局部变量、该返回到哪);函数返回,这层就弹掉。

**递归没有任何新机制**:函数调用自己,只不过是栈上**连续压了好几层同一个函数**,每层的参数不同而已。如果递归写崩了,ASan/调试器给你看的将是:

```
#0 fact fact.c:3
#1 fact fact.c:4
#2 fact fact.c:4
#3 fact fact.c:4
... (几万层)
#xxxx main
```

同一个函数名叠几万层——这就是**栈溢出**的长相。所以先记住物理本质:**递归 = 在调用栈上叠罗汉,叠得完就能算出来,叠不完就塌**。

## 12.1 两条腿,缺一条就摔

每个能跑的递归函数必须有:

1. **基线(base case)**:小到不用递归、直接给答案的情况。它是"叠罗汉的地板"。
2. **递缩(recursive case)**:调用自己,但**问题必须变小**,保证一步步逼近地板。

```c
int fact(int n) {
    if (n <= 1) return 1;      // 基线:地板
    return n * fact(n - 1);    // 递缩:n 严格变小,朝地板走
}
```

自查清单,以后每写一个递归就问三句:
- 地板在哪?(没有 → 无限叠 → 栈溢出)
- 每次调用问题真的变小了吗?(`fact(n)` 里手滑写 `fact(n)` → 原地踏步 → 栈溢出)
- 所有输入都够得着地板吗?(基线写 `n == 1`,别人传个 0 进来,0→-1→-2→… 永远撞不上 1 → 栈溢出。所以用 `n <= 1` 兜底)

## 12.2 两种读法:机械展开 vs 信任接口

**机械展开**(小输入验证时用):

```
fact(4)
= 4 * fact(3)
= 4 * (3 * fact(2))
= 4 * (3 * (2 * fact(1)))
= 4 * (3 * (2 * 1))        ← 触底
= 24                        ← 逐层弹栈算回来
```

注意一个关键细节:`4 *` 这个乘法**在 fact(3) 返回之前是没法做的**——它挂在栈上等。这就是为什么深递归费内存:每一层都有人在"等下面的结果"。

**信任接口**(写代码、读代码时用):写 `fact(n)` 的时候,**直接假设 `fact(n-1)` 已经是个好用的现成函数**,你只负责"拿到 (n-1)! 之后怎么拼出 n!"。别在脑子里展开三层——人脑栈只有两三层深,展开必乱。这个心法叫**递归信任**:地板和递缩都检查过了,中间过程交给机器。

类比:你在 10 章用 `make_node` 时,从不重新想一遍 malloc 怎么工作——**对自己刚写的函数你都能黑盒信任,对"自己"当然也可以**。递归难就难在心理上,不在技术上。

## 12.3 链表是递归的天然教具

看一眼你自己的 `Node` 定义:`struct Node` 里面装着 `struct Node *`——**类型定义本身就是递归的**。所以这个视角成立:

> **一条链表 = 一个结点 + 一条更短的链表。** (空链表是地板)

你 10 章用循环写的函数,几乎每个都有递归孪生版。对照着看(下面用**不带哨兵**的视角,head 直接指第一个数据结点——递归里裸链表更顺,原因见 12.5 思考题):

```c
// 求长度:一条链表的长度 = 1 + 剩下那截的长度
int length_r(Node *head) {
    if (head == NULL) return 0;        // 地板:空链
    return 1 + length_r(head->next);   // 递缩:链变短
}

// 正序打印:先打自己,再打剩下的
void print_r(Node *head) {
    if (head == NULL) return;
    printf("%d\n", head->data);
    print_r(head->next);
}
```

现在,**单链表章节留下的一个"不可能任务"**——单链表不能倒着走(没有 prev)——递归轻描淡写就解决了:

```c
// 倒序打印:先让"剩下的"全打完,最后才打自己
void print_reverse_r(Node *head) {
    if (head == NULL) return;
    print_reverse_r(head->next);   // ← 就是把这两行对调!
    printf("%d\n", head->data);
}
```

为什么这能倒序?因为"打自己"这件事**挂在栈上等**,等最深那层(最后一个结点)先打完,再逐层弹回来打——调用栈免费送了你一条回头路。**"动作放在递归调用之前还是之后",决定正序还是倒序**——这一句就是二叉树前序/后序遍历的全部秘密,408 的送分点与送命点。

再来一个你有血泪记忆的:释放链表。10 章你用循环 + tmp 指针小心翼翼(free 之后不能再碰 `cur->next`)。递归版:

```c
void free_r(Node *head) {
    if (head == NULL) return;
    free_r(head->next);   // 先送走后面所有人
    free(head);           // 最后送走自己
}
```

思考:这两行**能对调吗**?对调后先 `free(head)` 再 `free_r(head->next)`——刚 free 完就摸 `head->next`,这是什么罪名?ASan 会报哪个词?(你太熟了。)——所以释放必须是"后序":先处理子结构,再动自己。二叉树的销毁同理。

## 12.4 什么时候别用递归

| | 循环 | 递归 |
|---|---|---|
| 内存 | O(1),几个变量 | O(深度),每层压一次栈 |
| 深度上限 | 无 | Mac 默认栈约 8MB,粗算几十万层封顶 |
| 适合 | 线性重复(数组、链表顺序遍历) | **结构本身递归**(树、分治、回溯) |
| 408 考法 | 写循环代码 | 读递归代码、写遍历、算递归式 |

经验法则:**链表用循环(它是线性的,递归纯属练习);树用递归(它每个结点岔两条路,循环写起来反而要自己手动管一个栈)。** 这章拿链表练递归,是因为你手上有现成的链表——真正的主场在树。

顺带认识两个词(408 选择题爱考):
- **斐波那契朴素递归** `fib(n)=fib(n-1)+fib(n-2)` 是 O(2ⁿ) 的经典反面教材——不是递归慢,是**重复计算**慢(fib(3) 被算了无数遍)。
- **尾递归**:递归调用是函数的最后一个动作、返回值不再加工(`return fact(n-1, acc)`)。编译器开优化能把它变成循环。知道概念即可。

## 易错点

1. 三大栈溢出成因,全在 12.1 的自查清单里:没地板 / 问题没变小 / 有输入够不着地板。
2. 先 free 再递归 = use-after-free(12.3)。释放类操作永远"后序"。
3. 递归函数里的局部变量,**每层各有一份**,互不干扰——这是压栈送的,不用怕"变量被下一层改了"。
4. 读递归代码别在脑里展开超过两层,用"信任接口"读法;需要精确验证就拿 n=2、n=3 笔算。

    if (head == NULL || head->next == NULL) return head;

## 12.5 通往树的桥(预告,不布置作业)

二叉树结点,你一眼就能看穿:

```c
typedef struct TreeNode {
    int data;
    struct TreeNode *left;    // 两个"next"
    struct TreeNode *right;
} TreeNode;
```

**一棵树 = 一个根 + 左子树 + 右子树**,地板是空树(NULL)。于是:

```c
void inorder(TreeNode *root) {
    if (root == NULL) return;     // 地板,和链表一模一样
    inorder(root->left);
    printf("%d ", root->data);    // "动作"夹在两次递归中间 → 中序
    inorder(root->right);
}
```

动作放最前 = 前序,放中间 = 中序,放最后 = 后序——**就是例 12.1 那道题**。你已经站在 408 二叉树的门口了,推门就进。
