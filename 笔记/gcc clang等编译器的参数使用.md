# gcc / clang 编译器参数使用

> gcc 与 clang 的参数基本通用。这些参数各有来历，理解名字的由来，记起来就容易多了。

## 速查表

| 参数                   | 缩写来源                        | 作用             | 使用场景              |
| -------------------- | --------------------------- | -------------- | ----------------- |
| `-o`                 | **o**utput                  | 指定输出文件名        | 每次都用              |
| `-c`                 | **c**ompile only            | 只编译不链接，生成 `.o` | 多文件项目 / Makefile  |
| `-g`                 | debu**g**                   | 生成调试信息         | 用 gdb/lldb 调试前必加  |
| `-fsanitize=address` | **f**lag + sanitize         | 内存错误检测（ASan）   | 调试段错误、内存越界        |
| `-Wall`              | **W**arnings: all           | 开启常用警告         | 日常必开              |
| `-Wextra`            | **W**arnings: extra         | 额外警告           | 配合 `-Wall`        |
| `-Werror`            | **W**arnings as **error**s  | 警告当错误，拒绝编译     | 强迫写干净代码           |
| `-O0`~`-O3`          | **O**ptimize                | 优化级别           | 调试 `-O0`，发布 `-O2` |
| `-Os`                | Optimize for **s**ize       | 优化体积           | 嵌入式等场景            |
| `-std=c11`           | **st**an**d**ard            | 指定 C 标准版本      | 408 / 王道代码用 c11   |
| `-lm`                | **l**ink library + **m**ath | 链接数学库          | 用了 `sqrt`、`pow` 等 |
| `-I`                 | **I**nclude                 | 头文件搜索目录        | 第三方库              |
| `-L`                 | **L**ibrary path            | 库文件搜索目录        | 第三方库              |

## 日常固定用法

现阶段练习就固定用这一条：

```bash
gcc -g -Wall -fsanitize=address -std=c11 main.c -o main
./main
```

翻译成人话：带调试信息、开启常用警告、启用内存检测、按 C11 标准，编译 main.c 输出为 main。

可以在 shell 配置里做个别名省得每次敲：

```bash
alias gcs='gcc -g -Wall -fsanitize=address -std=c11'
# 之后就能 gcs main.c -o main
```

交作业或跑性能测试时，换成去掉调试和检测、开优化的版本：

```bash
gcc -O2 -std=c11 main.c -o main
```

## 详解

### 最基本的一组

```bash
gcc main.c -o main
```

**`-o`** 是 output（输出）的缩写，指定生成的可执行文件叫什么名字。不加的话，默认输出一个叫 `a.out` 的文件——这个名字是历史遗物，是 assembler output（汇编器输出）的缩写，从 1970 年代的 Unix 一直沿用到今天。

**`-c`** 是 compile only（只编译），只编译到目标文件（`.o` 文件），不进行链接。写多文件项目时会用到：先把每个 `.c` 分别 `-c` 编译成 `.o`，最后再链接到一起。写单文件链表练习暂时用不上，但以后写大项目、用 Makefile 时它是核心。

### 调试相关

**`-g`** 是 generate debug info（生成调试信息）。它把源代码的行号、变量名等信息嵌入可执行文件，这样 gdb 或 lldb 调试时才能显示"第 42 行，变量 p 的值是……"而不是一堆汇编地址。调试段错误的前提就是编译时加了 `-g`。

**`-fsanitize=address`** 启用 AddressSanitizer 内存检测。`-f` 这个前缀代表 flag，是一大类"开关型"选项的统一前缀，用来启用或关闭编译器的某个具体功能，比如 `-fno-inline`（禁止内联）。

### 警告相关

**`-Wall`** 字面是 Warnings: all（所有警告），不过名字有点名不副实——它其实只开启"常用的一批"警告，并不是真的全部。比如变量定义了没用、函数忘了返回值、`if (a = b)` 把比较写成了赋值，这些低级但致命的错误它都会提醒你。

**`-Wextra`** 在 `-Wall` 基础上再加一批额外警告。

**`-Werror`** 是 Warnings as errors（把警告当错误），一旦有警告就拒绝编译通过。对初学者是好事，强迫你写干净的代码。

`-W` 前缀就是 Warning 的 W，所有警告类选项都归它管。

### 优化相关

**`-O0` / `-O1` / `-O2` / `-O3`** 中的 O 是 Optimize（优化），数字是优化级别：

- `-O0`：完全不优化（默认）
- `-O2`：发布软件最常用的级别
- `-O3`：最激进
- `-Os`：优化体积（size）

> ⚠️ **关键：调试时用 `-O0`，不要开优化。** 优化器会重排、合并甚至删除你的代码，导致 gdb 单步调试时执行顺序跟源码对不上，变量也可能"被优化掉了"看不到值。

### 标准版本

**`-std=c11`** 中 std 是 standard（标准），指定用哪个版本的 C 语言标准编译，比如 `c99`、`c11`、`c17`。408 和王道教材的代码用 `c11` 就够了。不指定时 gcc 有自己的默认值（通常是带 GNU 扩展的版本，如 `gnu17`）。

### 链接库

**`-lm`** 中的 `-l` 是 link library（链接库），后面紧跟库名。`-lm` 就是链接数学库（m = math），用了 `sqrt`、`pow` 这些函数就得加它，否则链接时报 undefined reference。

> ⚠️ **初学者最常撞到的坑之一**：头文件 `#include <math.h>` 只是声明，函数的实现在库里，得靠 `-l` 链接进来。

**`-I`**（大写 i，Include）指定头文件搜索目录，**`-L`** 指定库文件搜索目录。以后用第三方库时会碰到。

## 记忆框架

这些参数的首字母几乎都直接对应功能——**o**utput、debu**g**（g 取自 debug 的尾音，历史上就这么定了）、**W**arning、**O**ptimize、**std**、**l**ibrary。搞懂缩写来源后，你会发现编译器参数不是乱码，是一套速记系统。
