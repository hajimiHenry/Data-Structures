# 11 双链表与循环链表

> 前置:你已经在 `练习/10-单链表` 里写出了带头结点的单链表全套(init / push / insert / remove / clear / destroy),并且知道**头结点(哨兵)吃掉特判**这件事。这一章就是把这个思想推到极致:**双向 + 循环 + 哨兵 = 零特判链表**。这也是 408 和 Linux 内核里真正在用的形态。

## 11.0 先算旧账:你的单链表还有三个痛点

拿出你自己的 `list.c`,对着代码回答(别凭印象,翻代码):

1. `push_back` 要从头走到尾才能挂新结点——链表 1 万节就走 1 万步。**尾插 O(n)**。
2. `list_remove` 里你专门养了个 `bef` 指针尾随 `cur`——因为**知道一个结点,却拿不到它的前一个**。
3. 想从最后一个结点倒着打印回来?对不起,箭头全是单向的,**回不了头**。

三个痛点同一个病根:**结点只记得"下一个是谁",不记得"上一个是谁"**。药方显而易见——每个结点多存一根往回指的箭头。

## 11.1 双链表结点:两根箭头

```c
typedef struct DNode {
    int data;
    struct DNode *prev;   // 往回指
    struct DNode *next;   // 往前指
} DNode;
```

内存图(普通双链表,还没上循环):

```
NULL ← [p|10|n] ⇄ [p|20|n] ⇄ [p|30|n] → NULL
```

类比:单链表是**单行道**,错过路口只能绕一整圈;双链表是**双向车道**,随时掉头。代价:每个结点多付一个指针的内存(8 字节),以及——**每次改链要维护两倍的箭头**。这就是本章的全部难度所在。

## 11.2 核心功夫:数箭头

单链表插入动 2 根箭头,删除动 1 根。双链表翻倍:

**在结点 p 后面插入新结点 n,要动 4 根箭头。** 画图,一根根数:

```
插入前:  [p] ⇄ [q]          (q 是 p 原来的下一个)
插入后:  [p] ⇄ [n] ⇄ [q]

① n->next = p->next;    // n 的前爪搭住 q
② n->prev = p;          // n 的后爪搭住 p
③ p->next->prev = n;    // q 回头认 n(注意:此时 p->next 还是 q,所以要在④之前做!)
④ p->next = n;          // p 认 n
```

**顺序有讲究**:④ 一旦先做,`p->next` 就不再是 q,③ 里的 `p->next->prev` 会摸到 n 自己头上——接线接出自环。**口诀:先把新结点的两只爪子搭好(①②),再让旧结点回头(③),最后才断旧线(④)。** 其实只要 ③ 在 ④ 前面,①② 顺序随意——想明白为什么。

**删除结点 p,动 2 根箭头**(这次连遍历找前驱都不用了,`p->prev` 直接就是):

```
删除前:  [a] ⇄ [p] ⇄ [b]
删除后:  [a] ⇄ [b]

① p->prev->next = p->next;   // a 绕过 p
② p->next->prev = p->prev;   // b 绕过 p
然后 free(p)
```

对照表(和你 10 章的手感接上):

| | 单链表 | 双链表 |
|---|---|---|
| 插入动几根箭头 | 2 | 4 |
| 删除动几根箭头 | 1 | 2 |
| 删 p 需要什么 | 得先遍历找到 p 的前驱 | `p->prev` 白送 |
| 尾插 | O(n) 走到底 | 等上循环后 O(1)(见下节) |

## 11.3 上循环 + 哨兵:特判的终结

上面 11.2 的代码你应该已经闻到危险了:如果 p 是尾结点,`p->next->prev` 就是 NULL 解引用——又要写 `if (p->next != NULL)` 特判。头尾各一堆,和你 10 章前半段的特判地狱一模一样。

10 章你怎么解决的?**哨兵(头结点)让第 1 个结点有了前驱**。现在把这招用到两头:

**双向循环链表:哨兵的 next 指第一个结点,prev 指最后一个;尾结点的 next 绕回哨兵。** 整条链首尾咬合成一个环,哨兵是接缝:

```
        ┌──────────────────────────────┐
        ↓                              │
   [哨兵 H] ⇄ [10] ⇄ [20] ⇄ [30] ⇄──┘
   (data 不用)

空表:  H 的 next 和 prev 都指向 H 自己(自己咬自己的环)
```

这个结构的美妙之处,一条条数:

1. **NULL 从世界上消失了**。任何结点的 prev/next 都指向真实结点(最差也是哨兵),11.2 的插入删除代码**一个 if 都不用加**,原样就是对的。
2. **尾插 = 在哨兵前面插**,`insert_before(H, data)`,O(1)!因为 `H->prev` 就是尾结点——不用遍历了。痛点 1 卒。
3. **倒序遍历**:从 `H->prev` 出发沿 prev 走到 H。痛点 3 卒。
4. 空表判断:`H->next == H`。

| 判断 | 你的 10 章单链表(带哨兵) | 双向循环(带哨兵) |
|---|---|---|
| 空表 | `head->next == NULL` | `head->next == head` |
| 遍历终点 | `cur == NULL` | `cur == head`(回到哨兵) |
| 尾结点 | 一路走到 `next==NULL` | `head->prev` 直接拿 |

⚠ **最大的思维切换:遍历的"到底了"不再是 NULL,而是"绕回哨兵"**。你 10 章写的所有 `while (cur != NULL)`,在这里全部换成 `while (cur != head)`(cur 从 `head->next` 出发)。忘了换就是死循环——环上没有 NULL,永远走不到。

## 11.4 循环单链表与约瑟夫问题

不加 prev、只把尾结点的 next 绕回头,就是**循环单链表**。408 里它的经典应用是**约瑟夫环**:n 个人围一圈,从 1 号开始报数,报到 m 的人出列,然后从下一个人重新报数,直到只剩一人。

用循环链表解:m-1 步走到出列者的前一个,摘掉一个结点,继续。链表天然是环,"绕圈"这个动作免费——这就是选它的理由。

(注:约瑟夫用不带哨兵的裸环写更顺,因为哨兵会干扰报数。所以这题顺便逼你复习"没有哨兵怎么删结点"——旧功夫不能丢。)

## 易错点

1. **插入 4 根箭头,顺序错了自环**:`p->next = n` 千万别抢在 `p->next->prev = n` 前面。拿不准就先画图再抄图写码。
2. **遍历终止条件**:循环链表用 `!= head`,不是 `!= NULL`。混写 = 死循环。
3. **只改了一半箭头**:双链表每次操作 prev 和 next 都要照顾,漏一根,正着走没事、倒着走就翻车——所以**每个测试都要正反各遍历一次**才算验过。
4. 删除后 free 前,先确认两边都绕过去了(顺序:先接线后 free——10 章的 use-after-free 还记得吧,这里犯了 ASan 照样抓你)。

```
DNode *dlist_init(void);                     // 造哨兵,自己咬自己
void   insert_after(DNode *p, int data);     // 在结点 p 后插 —— 4 根箭头的主战场
void   insert_before(DNode *p, int data);    // 想想:能不能一行调用 insert_after 搞定?
void   push_front(DNode *head, int data);    // = insert_after(head, ...) 一行
void   push_back(DNode *head, int data);     // = insert_before(head, ...) 一行,O(1)!
void   remove_node(DNode *p);                // 摘掉 p 本人(不许传哨兵,想想怎么防)
void   print_list(DNode *head);              // 正序
void   print_reverse(DNode *head);           // 倒序 —— 双链表的招牌菜
int    length(DNode *head);
void   dlist_clear(DNode *head);             // 清空,哨兵可复用
void   dlist_destroy(DNode *head);           // 全拆
```

注意这套接口和 10 章的不同:insert/remove 直接收**结点指针**而不是序号——因为双链表的意义就是"手里有结点就能 O(1) 操作"。(想按序号删?先写个 `DNode *get(DNode *head, int seq)` 再喂给 remove_node,组合出来。)
